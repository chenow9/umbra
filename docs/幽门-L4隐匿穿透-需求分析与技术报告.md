## 0. 结论先行

你要的不是再做一个 NPS，也不是再包一层 Pangolin，更不是给 frp 套一个面板。  
核心是五件事叠在一起：

1. L4 only（TCP/UDP）
2. **服务端改映射即生效，节点侧不改配置、不重启**（NPS 的控制模型，frp 默认做不到）
3. 动态绑端口，不重启入口、不断已有连接（Pangolin/Orbien 做不到）
4. 默认对扫描不可见（Visitor / SPA）
5. 可审计的流量统计 + 简约管理面

**推荐路线（v0.2 修订）：**

- **控制面自研（Go）**：节点只带「入口地址 + 设备凭证」上线；映射、模式、ACL 全部存在服务端，经控制通道 **push** 到已在线节点。
- **隐匿层自研**：nftables 默认 DROP + SPA 信标；Visitor 模式入口不开业务口。
- **数据面自研 L4 splice**（TLS 1.3 + yamux：控制 JSON 与字节流分流）。frp **不对用户暴露**——不发 frpc.toml、不要求 `frpc reload`。不内嵌 frp。Visitor 只做本机 L4（TCP/UDP）。
- 入口跑宿主机 / host 网络，映射是运行期 `Listen`。
- 管理面简约 Web：节点、映射、流量、审计。管理面本身不裸奔。

配套接口见 [M1 接口草案](./M1-接口草案.md)。

## 1. 需求理解（已对齐）

### 1.1 用过的产品与结构性不满

**NPS**  
形态正确：npc 几乎只配 `server_addr` + `vkey`，隧道全在服务端 Web 里建，在线客户端立刻执行。  
弃用理由仍然成立：停更、CVE-2022-40494 等认证绕过、默认口令、IDOR。要的是它的 **控制模型**，不要它的代码和安全基因。

**Pangolin**  
L7 + Identity 完整；raw TCP/UDP 要改 Traefik 静态 entrypoint + compose 端口 + 重启。波动是结构问题。

**Orbien**  
必须先声明 `port_pool` 并在 Docker 里把整段端口映射进去，后台才能用。端口是部署期静态资源。

**frp**  
隧道与热更新成熟，但 **配置真相在客户端**：`frpc.toml` + `frpc reload`，或打客户端自己的 Store API。服务端改完，客户端不改就不生效。这正是你不能接受的。frp 的 Store 仍写在 **frpc 本机**，不是 NPS 那种「服务端下发任务」。

### 1.2 目标产品

一台公网入口 + N 台 NAT 后 节点：

1. 只做 L4：TCP、UDP。
2. **配置唯一真相在服务端。** 节点安装后只保留入口地址与凭证；之后增删改映射只在 Web/API 操作，已在线节点秒级执行，不碰客户端文件、不重启 节点、不重启入口。
3. 入口运行时 bind/释放端口，不影响其它映射的在途连接。
4. 默认隐匿（Visitor / SPA）；公开端口是显式模式。
5. 流量可统计（实时速率 + 累计，按节点/ 按映射）。
6. 管理界面简约。
7. 安全基线远高于 NPS。

### 1.3 非目标

- 用户流量 L7 反代、自动证书、IdP
- 把 frpc.toml 当作产品配置面
- 兼容 NPS 协议/配置
- 非特权 Docker 里任意绑宿主机端口
- v1 全量 Mesh VPN / P2P

### 1.4 v0.2 补充条款（已纳入范围）

**S1. 服务端配置热下发（P0，否决 frp 式客户端改配置）**

- 节点本地配置允许且只允许：入口地址、设备凭证、可选日志级别。
- 映射、端口、协议、模式、ACL、开关 **禁止** 出现在 节点配置文件里作为用户操作步骤。
- 服务端保存后：若 节点在线，控制通道立即 push diff；若离线，上线后在 Hello 里带全量映射。
- 成功标准：管理员在面板新建 TCP 映射 → 不登录内网机器 → 用该端口从外网打到内网服务。
- 实现上 节点可以有内部状态缓存（崩溃恢复），但对用户不可见、不可编辑。

**S2. 流量统计（P0）**

- 维度：全站 / 节点/ 映射。
- 指标：入站字节、出站字节、当前连接数、累计连接、当前速率；UDP 另计报文数。
- 时间：实时（秒级）+ 今日/7 日/30 日累计；保留可画图的时序（默认 10s 采样，至少 7 天）。
- 面板上可直接看到，不靠看日志。
- 不按包存原始流量（那是抓包，不做）。

**S3. 界面简约（P0，体验）**

- 不是身份平台，不是监控套件。一屏能看完：哪些 节点在线、哪些映射在跑、流量是否异常。
- 创建映射一步完成，不是向导。
- 少色彩、少卡片堆砌、无营销文案、无装饰插画。
- 设计语言见第 9.2 节。

## 3. 场景与模式

| 模式 | 公网表现 | 谁能连 | 适用 |
|---|---|---|---|
| A. Visitor | 无业务端口 | 访客客户端 | SSH/RDP/库 |
| B. SPA 暗端口 | 扫到 filtered | 先 SPA 再连 | 不能装 Visitor 时 |
| C. 公开映射 | 正常 open | 任何人（可 IP 白名单） | 游戏、语音 |

公开端口仍必须满足：创建/删除不重启、不断其它连接；并计入流量统计。

## 4. 功能需求

### 4.1 控制面（P0）

- 节点注册：一次性安装码 → 设备凭证，可吊销。
- 映射 CRUD，字段：协议、模式、入口端口、目标 host:port、ACL、限速、空闲超时、开关。
- **保存即下发**：在线节点无文件变更、无进程重启。
- 入口动态 `Listen` / `Close`；删除可排空已有连接。
- 管理员鉴权：无默认口令；写操作进审计。

### 4.2 数据面（P0）

- TCP 字节流转发；UDP 会话表 + 空闲超时。
- 节点主动出站，多路复用。
- 隧道加密（TLS1.3 或 Noise）。
- 热更新只影响新连接。

### 4.3 隐匿（P0）

- SPA：单包、加密、HMAC、时间窗、防重放；nftables TTL 放行。
- 信标口对探测静默。
- 不做经典 knockd 序列。

### 4.4 流量统计（P0，v0.2）

见 1.4 S2。控制通道心跳携带增量计数器，服务端聚合落库。以入口侧计数为准（节点侧作为对照）。

### 4.5 节点（P0）

- 单文件；配置三项以内。
- 断线重连；重连后拉取全量映射并与本地运行态对齐（多的停、少的开）。
- Linux amd64/arm64。

### 4.6 Web（P1 实现，P0 设计约束）

- 页：总览、节点、映射、流量、审计。
- 简约，见 9.2。

### 4.7 明确不做（v1）

L7 反代、TUN、P2P、抓包、文件服务、客户端 toml 工作流。

## 5. 威胁模型（摘要）

扫描、协议探测、SPA 重放、伪造 UDP 源 IP、盗取 节点盘、打 Web 控制面（NPS 死因）、把入口当跳板。

硬约束：默认 DROP；SPA 有时间窗+nonce；控制面与数据面分离；凭证可吊销；映射目标默认仅 RFC1918/本机；不做 L7 解析。

## 6. 数据面选型修订（相对 v0.1）

v0.1 建议「控制面包 frp」。S1 之后这条不成立：

| | 用户改客户端配置 | 服务端改即对已在线客户端生效 | 暗端口 | 流量统计 |
|---|---|---|---|---|
| 原版 frp | 必须（toml / 客户端 Store） | 否 | 无 | dashboard 有，但是客户端视角 |
| 用 API 去改每台 frpc | 用户可不改，但你要能打到每台 frpc 管理口 | 勉强 | 仍要自己做 | 要再包一层 |
| NPS 模型 | 否 | 是 | 无 | 有 |
| **幽门** | **否** | **是** | **要做** | **要做** |

给每台 frpc 开管理 API 再由服务端去「遥控 reload」，等于：

- 多一个必须打到内网客户端的控制面（方向反了，节点才应该主动出站）
- 配置真相分裂（DB vs frpc 的 db.json）
- 用户一旦看到 frp，又会去改 toml

因此 v1 **自研控制协议**：节点出站一条 TLS 连接，服务端 push `MappingSync`。这是 NPS 做过的事，实现量远小于自研一套新隧道密码学；转发就是 `io.Copy` / UDP 会话表。

frp 仍可借鉴：yamux 多路、STCP 对应 Visitor、心跳与压缩。不引入用户可见的 frps/frpc。

## 7. 关键机制

### 7.1 无重启绑端口

入口 host 网络；Go `Listen`/`ListenUDP` 即时生效；nftables 运行期规则；云安全组放行端口段。控制面与数据面宜分进程或至少分 goroutine 组，重载 UI 不动转发。

### 7.2 服务端下发（S1）

```
节点  --Hello(id, cred, version)-->  Server
Server --HelloOk(full mappings)-->   节点
          …在线期间…
Server --MappingSync(upsert/delete)--> 节点
节点  --Ack(status)-->              Server
节点  --Heartbeat(stats delta)-->   Server
```

节点运行态 = 服务端映射表的投影。禁止「以本地 toml 为准再向服务端申报」。

### 7.3 隐匿

- Visitor：入口不 Listen 业务口（对标 frp STCP，但是配置在服务端，访客凭证也在服务端签发）。
- SPA：UDP 信标静默；通过后 nftables `saddr + dport accept timeout`。
- 公开：Listen + 允许策略，计入统计。

TCP 暗端口必须在内核丢 SYN，否则一定是 open。

### 7.4 流量计数

每个 splice 两边 `countingConn`：`bytes_in/out` 原子加。UDP 按报文和字节。10s 刷入 `traffic_samples`。心跳只传增量，避免时钟回拨导致双计。面板读聚合表，不扫连接。

## 8. 架构

```
  管理员 ──简约 Web / API──► umbrad（控制面：映射真相、审计、统计聚合、SPA、nftables）
                                    │ push MappingSync
                                    │ 动态 Listen
  扫描者 ──DROP──✕                 │
  合法用户 ──(SPA/公开/Visitor)──► 数据面 splice ──TLS mux── 节点（零映射配置）
                                                              └─ 只转 local host:port
```

模块：`umbrad`（Go）、`umbra-node`（Go）、`umbra` CLI（knock / visit）、Web。

权限：一次性 bootstrap → 设备证书；节点只能执行指派给自己的映射；禁止默认口令；控制面绑回环或暗端口。

## 9. 技术栈与界面

### 9.1 后端

Go；`crypto/tls` 或 Noise；多路复用用 yamux（Apache-2.0）一类，不引入用户可见的 frp。nftables netlink。SQLite 单节点。

### 9.2 界面语言（简约）

- 纸与墨：浅色底或深灰底二选一，**一套**中性色 + **一个**强调色（建议墨绿/石板，不用紫、不用大渐变）。
- 字体不超过两种；数字用等宽（流量、端口）。
- 布局：左窄导航（总览 / 节点/ 映射 / 流量 / 审计）+ 主表。主表一行一条映射，状态用小圆点而非彩色大徽章。
- 主操作一个：右上「新建映射」。表单单页：节点、协议、模式、入口端口、目标、是否公开。
- 总览三块数字：在线节点、活跃映射、今日流量。下边一张速率图，一张告警/审计。
- 空状态一句话 + 一个按钮，不放插画。
- 密度偏低，留白优先；移动端可扫表，不把运维台做成 App 营销页。

## 11. 风险（增补）

| 风险 | 缓解 |
|---|---|
| 自研控制通道延期 | M1 只做 JSON-over-TLS + 明文映射下发（仍加密传输层），不做新密码学协议 |
| 计数不准 | 入口侧为权威；节点侧只作对照；只用增量 |
| 用户仍想「像 frp 一样改客户端」 | 产品上不提供这条路径，文档写死 |
| 简约做成空 | 总览必须有三个数字和一张图，映射表必须能在 3 次点击内建好 |

## 12. 一句话范围（冻结）

> 做一款 Go 实现的自托管 L4 内网穿透网关：节点只持入口地址与凭证；所有映射在服务端修改并热下发；入口运行时绑定/释放 TCP·UDP 且不重启、不断已有连接；默认对扫描不可见（Visitor 或 SPA）；公开端口为显式模式；提供按节点/映射的流量统计；管理界面简约；不提供用户流量 L7 反代；不对用户暴露 frp 配置模型。
