# 幽门 M1 接口草案

> 配套：`幽门-L4隐匿穿透-需求分析与技术报告.md` v0.2  
> 状态：草案，实现前可小改字段名，不可改「服务端为真相 / 节点零映射配置」  
> 日期：2026-08-26  
>
> **实现对照（2026-08-27）：** 管理面与 API 由 `umbrad -http` 同一端口提供（默认 `:8080`），路径 `/v1/...`。节点控制通道仍是 `:4400` TLS。旧参数 `-api` 只作覆盖 `-http` 的别名，不再单独开 4401。

本文包含：数据模型、管理 HTTP API、节点控制通道、流量与下发语义、nftables 模板、M1 验收。

---

## 1. 原则

1. **配置唯一真相是服务端数据库。** 节点不申报映射列表，只接收并执行。
2. **下发是 push，不是「等客户端 reload 文件」。**
3. **计数权威在入口。** 节点上报增量只作对照与离线补齐。
4. 管理 API 与 节点通道分离：不同端口、不同证书、不同协议。
5. 错误可机器读：`{ "error": { "code", "message", "details" } }`。

## 2. 数据模型

### 2.1 节点

```
id            string  ULID
name          string
comment       string
bootstrap     一次性安装码（只在创建时返回明文，落库只存哈希）
cred_fp       设备证书指纹
status        online | offline | revoked
addr          最近观察到的出口 IP（展示用，不做 ACL 依据）
version       agent 版本
os            linux
arch          amd64 | arm64
last_seen     time
enabled       bool
created_at    time
```

节点本地文件（用户可见的全部）：

```toml
# /etc/umbra/agent.toml
server = "gate.example.net:4400"
token  = "umbra_dev_..."          # 或证书路径
# 禁止在此出现 mappings / ports
```

### 2.2 Mapping

```
id            string  ULID
node_id      string
name          string
proto         tcp | udp
mode          visitor | spa | public
entry_port    uint16 | null     # visitor 必须为 null
local_host    string            # 默认 127.0.0.1；默认拒绝非 RFC1918/本机
local_port    uint16
allow_cidrs   string[]          # 空 = 该模式下的默认策略
max_conns     uint | null
rx_bps        uint | null       # 入站限速，可选
idle_timeout  duration          # UDP 会话默认 60s
enabled       bool
created_at    time
updated_at    time
```

约束：

- 同一入口 `(proto, entry_port)` 全局唯一（visitor 除外）。
- `mode=visitor` 禁止 `entry_port`。
- `mode=public|spa` 必须 `entry_port`。
- 改 `node_id` 视为删旧建新，先排空。

运行态（不持久化为用户配置，可重建）：

```
listen_state    pending | listening | error | disabled
listen_error    string
active_conns    uint
bytes_in        uint64   # 自创建累计
bytes_out       uint64
```

### 2.3 TrafficSample

```
ts            time    # 对齐到 10s
node_id      string
mapping_id    string
bytes_in      uint64  # 该窗口增量
bytes_out     uint64
conns_opened  uint
conns_closed  uint
packets_in    uint    # UDP
packets_out   uint
```

聚合视图：`traffic_hourly` / `traffic_daily` 由采样表滚成。

### 2.4 SpaGrant

```
mapping_id    string
src_ip        inet
expires_at    time
created_at    time
```

内核规则与此表一致；进程重启时从该表重建 nftables。

### 2.5 Audit

```
ts        time
actor     string    # admin id 或 "agent:<id>" 或 "spa"
action    string    # mapping.create / mapping.push / node.revoke / spa.allow ...
target    string
ip        inet
detail    json
```

### 2.6 VisitorTicket

```
id          string
mapping_id  string
secret_fp   哈希
expires_at  time | null
label       string
```

签发时返回一次性明文，用于 `umbra-visit`（本机 L4）。

## 3. 管理 HTTP API

Base：`https://127.0.0.1:4410/api/v1`  
鉴权：`Authorization: Bearer <session>`（后续可加 OIDC）。  
全部写操作记审计。

### 3.1 会话

```
POST /login          { username, password } → { token, expires_at }
POST /logout
GET  /me
```

### 3.2 总览

```
GET /overview
→ {
    agents_online, agents_total,
    mappings_active, mappings_total,
    bytes_in_today, bytes_out_today,
    bps_in, bps_out,
    rejected_scans_today
  }
```

### 3.3 节点

```
GET    /nodes
POST   /nodes                 { name, comment } → { node, bootstrap, install_cmd }
GET    /nodes/:id
PATCH  /nodes/:id             { name, comment, enabled }
POST   /nodes/:id/revoke      吊销凭证，断开通道，映射标 error
POST   /nodes/:id/rotate      作废旧凭证，返回新 bootstrap（需节点重装或重登）
DELETE /nodes/:id             须无映射或 ?force=1
```

`install_cmd` 示例（用户复制即可，无第二份配置文件要改）：

```
curl -fsSL https://gate.example.net/install.sh | sh -s -- \
  --server gate.example.net:4400 --token umbra_boot_xxx
```

### 3.4 映射 —— 产品核心

```
GET    /mappings?node_id=&proto=&mode=&q=
POST   /mappings
PATCH  /mappings/:id
POST   /mappings/:id/enable
POST   /mappings/:id/disable
DELETE /mappings/:id           { drain: true }   # drain=排空再关
```

`POST /mappings` 体：

```json
{
  "node_id": "01J...",
  "name": "ssh-box1",
  "proto": "tcp",
  "mode": "spa",
  "entry_port": 40222,
  "local_host": "127.0.0.1",
  "local_port": 22,
  "allow_cidrs": [],
  "idle_timeout": "60s",
  "enabled": true
}
```

语义（必须同时发生，同一请求返回时已启动）：

1. 校验端口冲突、节点存在、目标地址策略。
2. 写入 DB。
3. 入口按 mode bind（visitor 不 bind）。
4. nftables：public 放行；spa 保持 DROP 直到 grant；visitor 无端口。
5. 若节点 `online`，立刻 `MappingSync` upsert；否则记 `pending`，等上线。
6. 返回 Mapping + `listen_state` + `push_state`（`acked` | `pending_offline` | `error`）。

**不存在的 API：** `POST /nodes/:id/reload`、`PUT /nodes/:id/config`。没有「请客户端重载」这一步。

### 3.5 流量

```
GET /traffic?range=1h|24h|7d|30d&node_id=&mapping_id=
→ {
    summary: { bytes_in, bytes_out, peak_bps_in, peak_bps_out, conns },
    series:  [ { ts, bytes_in, bytes_out, bps_in, bps_out } ]
  }

GET /mappings/:id/traffic?range=24h
GET /nodes/:id/traffic?range=24h
```

`range=1h` 用 10s 桶；`24h` 用 1min；`7d/30d` 用 1h。

### 3.6 SPA / Visitor 凭证

```
POST /mappings/:id/knock-demo     管理测试：把调用方 IP 写入 SpaGrant（仅管理网）
GET  /mappings/:id/grants
DELETE /grants/:id

POST /mappings/:id/visitors       { label, expires_at } → { ticket, command }
GET  /mappings/:id/visitors
DELETE /visitors/:id
```

访客命令示例：`umbra-visit --server gate.example.net:4400 --tls-ca ca.crt --ticket umbra_vis_... --local 127.0.0.1:2222`（只开本机 L4 TCP/UDP，不做 HTTP）

### 3.7 审计

```
GET /audit?from=&to=&actor=&action=
```

## 4. 节点控制通道

- 地址：`gate:4400`。TLS 1.3 上 **yamux**：第一条流是控制 JSON，其余流是 L4 数据（TCP 原样拷贝，UDP 按报文加长度前缀）。
- 传输：TLS1.3，客户端证书 = 设备凭证。Bootstrap token 只用于第一次 `Enroll` 换证。
- 控制消息：长度前缀 JSON。数据流首帧是 `StreamOpen { mapping_id, proto, peer }`，之后不再走控制 JSON。

### 4.1 帧

```
Enroll        C→S  { bootstrap, hostname, os, arch, version }
EnrollOk      S→C  { node_id, cert, key }          # 仅一次
Hello         C→S  { node_id, version }
HelloOk       S→C  { mappings: Mapping[] }          # 全量
MappingSync   S→C  { upsert: Mapping[], delete: [id] }
MappingAck    C→S  { id, ok, error }
Heartbeat     C→S  { ts, mappings: [{ id, bytes_in_d, bytes_out_d, active_conns }] }
OpenStream    双向  用户连接到来时，在 mux 上开一条流，首帧带 mapping_id
CloseStream
Revoked       S→C  {} 然后断开
```

### 4.2 对齐算法（防脑裂）

节点收到 `HelloOk` 或 `MappingSync`：

```
want = { m.id: m  for m in payload if m.enabled }
have = 本地已启动的转发器

for id in have - want:  停止转发器
for id in want - have:  启动（连 local_host:local_port 的拨号池）
for id in want ∩ have:  若 spec 指纹变化则停再起（已有连接按 mapping 的 drain 策略）
Ack 每一条
```

**节点不得**把本地多出来的映射「上报请服务端收录」。本地多出来的一律停掉。

### 4.3 用户连接（TCP）

1. 入口 accept（已过 nftables）。
2. 在到该 节点的 mux 上 OpenStream `{ mapping_id, proto, peer_ip, peer_port }`。
3. 节点 dial `local_host:local_port`，失败则回 `RST` 语义并计数。
4. 双向 splice，两边 counting。
5. 任一侧 EOF 则关流。

UDP：入口按 `(src, dst_port)` 建会话，复用一条 datagram 流或每会话一条流（M1 用每会话一条，简单）。

### 4.4 离线

节点断线：已 accept 的入口连接尽快关掉（隧道没了）；映射 `push_state=pending_offline`；入口是否继续 Listen：继续（避免端口被别人抢），但新连接立即失败。节点回来后 HelloOk 全量对齐。

## 5. nftables 模板（入口节点）

独立 table，避免和发行版规则缠在一起。

```
table inet umbra {
  set spa_allow {
    type ipv4_addr . inet_proto . inet_service
    flags timeout
  }

  set public_ports {
    type inet_proto . inet_service
  }

  chain input {
    type filter hook input priority 0; policy drop;

    ct state established,related accept
    iif lo accept
    tcp dport 4400 accept      # 节点出站连入（可再限 IP）
    udp dport 4411 accept      # SPA 信标（用户态静默非法包）

    ip daddr <self> ip saddr . proto . dport @spa_allow accept
    meta l4proto . th dport @public_ports accept
  }
}
```

- 创建 `mode=public`：`add element inet umbra public_ports { tcp . 25565 }`
- SPA 成功：`add element inet umbra spa_allow { 203.0.113.8 . tcp . 40222 } timeout 60s`
- 删除映射：从 set 里删，再 `Close` 监听。
- 默认 policy drop，未授权扫描 = filtered。

M1 可先只用 `public_ports` + 手工 CIDR，SPA set 放到 M2。

## 6. 流量语义

- `bytes_in`：从公网用户 → 入口 → 节点 → 本地（用户上传）。
- `bytes_out`：反向（用户下载）。
- 计数点：入口 splice 两侧，避免 节点侧 NAT 造成偏差。
- Heartbeat 里的 `*_d` 是自上次心跳的增量；服务端写入当前 10s 桶。重传不累加（带单调 `seq`）。
- 不把拒绝的 SYN 算进映射流量；可另计 `rejected_scans`（注意别当侧信道打日志明细）。

## 7. Web 信息架构（简约）

四页足够 v1：

| 页 | 内容 | 主操作 |
|---|---|---|
| 总览 | 三数字（在线节点、活跃映射、今日流量）+ 24h 速率图 + 最近审计 5 条 | 无 |
| Node | 表：名、状态点、地址、版本、流量 | 新建 节点（弹出安装命令） |
| 映射 | 表：名、节点、tcp/udp、模式、入口、目标、状态点、速率 | 新建映射（单页表单） |
| 流量 | 筛选 节点/映射 + 图 + 表 | 无 |

不设独立「设置向导」。审计可做总览下钻，不必第五个一级导航（若挤再加）。

创建映射表单字段顺序：名称 → 节点 → 协议 → 模式 → 入口端口（visitor 隐藏）→ 目标 host:port → 保存。保存成功留在表内，该行状态从 pending 到 listening，不弹成功页。

## 8. M1 验收清单

实现 M1 必须同时满足：

1. 新装 节点只有 server + token，无映射字段。
2. `POST /mappings` 后，不登录 节点机器、不改任何客户端文件，外网 TCP 可打到 `local_port`。
3. 再 `POST /mappings` 第二条，第一条的已有连接不掉。
4. `DELETE /mappings/:id` 后该口停止接受，其它口不受影响。
5. 节点进程重启：自动 Hello，映射恢复，仍无人工改配置。
6. 打流量后 `GET /traffic` 与映射行上的累计字节增加，方向正确。
7. 管理 API 未鉴权返回 401；节点错凭证无法 Enroll。

M1 可以没有：Web、SPA、UDP、Visitor、漂亮图表。有 HTTP API + CLI 即可。

## 9. 明确没有的接口

- 任何「下发 frpc.toml」「reload 客户端配置文件」
- 让 节点提交自己的映射清单供服务端采纳
- 在管理 API 上直接暴露 nftables 裸规则
- L7：Host、path、证书、upstream HTTP 头
