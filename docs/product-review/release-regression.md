## 实际升级验证

脚本从 v0.1.5 标签编译旧网关和旧节点，使用临时目录、回环地址生成三种 TCP 服务及访问票据。生成历史采样并明确保存配置后，用当前网关读取同一目录，保留旧节点进程与原凭证，验证配置 ACK、探测响应、服务字段、累计计数、历史曲线、票据与 CA。当前网关保存后，再运行旧网关进行同样检查。

控制数据 schema 仍为 2，流量历史 schema 仍为 1。已验证 v0.1.5 的已保存数据可以升级读取；本轮后端增加的探测错误字段为可选字段，没有重写持久化格式。

跨二进制试验关闭了登录，不能证明真实账户的双因素登录与会话在跨版本时全部无缝保留。Go 测试另行覆盖了双因素注册、会话、验证码重放、恢复码和 schema 1 迁移，但不等同于真实账户跨版本端到端验证。

更早的 schema 1 / 原始 JSON 有加载迁移路径。迁移会使旧会话失效，已有密码但尚未配置双因素认证的账户需完成迁移流程；没有逐一验证全部历史发布版本。回退试验仅限上述 v0.1.5 合成数据，不代表支持任意旧版本回退。

## 升级操作注意事项

- 备份完整的实际 `-tls-dir` 数据目录，包含 CA / 证书、`control.json`、`.prev`、`.tomb` 和 `traffic` 等文件；升级继续使用原目录，不重新生成 CA。
- 发现旧版累计流量约每 60 秒保存到控制数据，退出时 `FlushTraffic` 只刷新历史曲线。最近尚未保存的累计计数可能在停机后丢失；这不是格式迁移丢失。升级脚本先显式保存测试配置，以独立验证已落盘数据的兼容性。该停机保存问题尚未修复。
- `.tomb` 保存凭证撤销等安全状态；仅恢复旧 `control.json` 不能等同于完整回退，也不应绕过安全状态。

复跑跨版本试验：`node scripts/upgrade-smoke.mjs`。需要本地 Git 标签、Go 与 Node；只使用临时合成数据。
