# Umbra：从配置控制台到服务访问工作台

审查日期：2026-09-05。依据当前仓库、运行在 localhost:8080 的控制台和本次截图；未进行用户访谈，目标用户和任务频率是依据 README 的产品假设，不能当作使用数据。

## 产品理解

Umbra 是自托管的 TCP/UDP 内网服务访问网关。目标用户是家庭实验室用户、远程开发者、小团队运维。核心任务：让指定的人可靠地访问内网服务，并在失败时知道该处理哪里。

当前路径：部署入口 → 初始化口令和双因素 → 登记 Node → 执行命令 → 切换映射页面 → 填写协议/模式/端口/配额 → 保存 → 在更多菜单敲门、探测或签发 → 到部署页面找安装说明 → 在访问方运行命令。

隐含假设：用户以节点为思考单位；理解 public/spa/visitor；知道公网地址；配置下发就接近成功；主要需求是看流量；公开访问是合理默认；能分辨控制台本机地址与业务入口地址。这些假设不应继续支配产品。

## 如果今天重做

产品模型是“服务 = 目标 + 所属节点 + 访问策略”，节点是承载服务的基础设施，映射是 API/协议层实现名。一次接入的成功终点是得到明确连接方法，而非收到保存 toast。

信息架构：
- 服务：首页。全部服务、需处理、待确认、已停用，跨节点搜索，连接和编辑。
- 节点：接入、在线状态、凭证生命周期、该节点服务。
- 观测：流量和审计两个子视图，保留专业排障能力。
- 系统：管理员安全、安装与部署参考。

最短路径：已有节点 → 添加服务（目标/访问方式）→ 保存 → 服务连接面板 → 按需授权/复制地址或命令 → 显式探测与反馈。没有节点则直接进入节点接入；命令执行后自动观察上线，衔接创建。

连接面板明确展示节点、配置确认、入口、访问策略、最近探测。保护中的 SPA 与正常 visitor 不当作故障；节点在线/端口监听绝不等于外部客户端可达。公网地址来自服务端 advertise，不能猜测为浏览器 hostname（反向代理和 SSH 转发场景会错）。

功能边界：不引入 L7 网关、通用 SSH 终端或聊天机器人。AI 候选职责是解释故障链、生成配置草案和最小权限建议。用户仍决定目标、公开范围、凭证发放和真实网络探测；当前没有模型后端，不声称实现了 AI。

## 五项结构性决策与变更分类

| 决策 | 保留 | 删除 | 合并 | 重构 | 新增 |
| --- | --- | --- | --- | --- | --- |
| 服务作为首页 | 查询、筛选、启停、删除 | 统计型首页、隐式节点筛选 | 总览/映射 | 一个响应式服务列表 | 问题与待确认视图 |
| 目标导向接入 | TCP/UDP、ACL/限速/超时 | 演示端口、自动改写端口 | 新建后连接指导 | 分区表单、私有默认、字段校验 | 上线后继续添加服务 |
| 状态可信 | 推送确认、真实探测 | 虚假的“外网可连”、零响应成功 | 状态解释/下一步 | 统一诊断与探测结果 | 服务端业务入口地址 |
| 连接生命周期 | SPA、票据发放/撤销、CA | 签发后才可管理旧票据 | 连接/诊断/凭证 | 单服务面板 | 常驻票据管理入口 |
| 单一控制面 | Go 协议/控制/认证/持久化 | 未被调用的 TS 模拟控制面 | 前端操作与真实 API | typed payload + 拆分组件 | 回归测试 |

不改动现有服务的访问模式，不迁移或删除运行数据。新建 UI 默认 visitor；省略 mode 的旧 API 客户端继续使用既有 public 语义，避免隐式破坏协议。SQL 旧迁移历史不在本次删除范围，因为尚未证明历史环境可安全丢弃。

## 实施中进一步发现并处理的问题

- 创建 API 原本只返回 id/nodeId/name，前端却声明为完整 Mapping。现在创建与编辑都返回完整视图，创建后连接面板使用真实状态。
- 创建 API 原本没有拒绝已吊销节点，现与编辑 API 的有效节点检查对齐。
- 探测期间修改配置可能把旧目标响应归到新配置上。现在按 generation 校验，变化时返回 409 并要求重新探测。
- 配色同时存在 CSS 和 JavaScript 两套值，且运行时覆盖样式。删除 JS 颜色写入器，CSS 作为唯一颜色来源；十个装饰主题收敛为浅色/深色，旧深色偏好映射到深色。
- 新的默认视觉：深青导航、冷灰工作区、白色服务列表、青绿主操作；异常与待确认使用独立的文字和颜色，不仅靠颜色传达状态。
- 访问端命令原本使用服务器上的 `/etc/umbra/ca.crt` 路径，且没有就地安装指引。连接面板现在按访问方系统与架构给出客户端名称、下载入口、同目录 CA 指引和可直接运行的命令。

## 第二轮：视觉与交互重建

根据用户对上一版过于保守的反馈，进一步替换了控制台式布局：

- 固定侧栏改为顶部品牌导航；手机使用底部常驻导航。采用炭黑、暖白与荧光黄绿，加入日蚀品牌符号和服务数量主视觉。
- 四张统计卡收敛为带数量的筛选标签。服务改为响应式卡片，清晰呈现访问策略、协议、所属节点、目标与下一步。
- 全局快速入口支持 ⌘K / Ctrl+K，按服务、节点、地址、端口查找，方向键选择、回车进入服务或执行导航。不会通过快捷键自动授权或删除。
- 新建服务成为三步接入：目标 → 访问策略 → 确认。每步校验，返回修改保留草稿；编辑现有服务仍可直接完整修改。
- 连接工作区使用连接、诊断、凭证任务标签；异常服务默认打开诊断，正常服务默认打开连接。签发结果保留在面板状态中，切换标签不会丢失。

浏览器实测：桌面 1280px、平板 768px、手机 390px；非法端口阻止下一步、返回保留草稿、搜索回车打开服务、Ctrl+K、凭证与诊断标签、手机底部导航、深浅主题均通过。类型检查、改动文件 lint 与嵌入构建通过。

## 第三轮：从卡片首页到网络工作台

进一步移除宣传式大标题和大号数量图形，主页面改为入口、节点、服务目标的关系工作台。每个节点分支展示当前筛选范围内的服务；连线只表达配置归属，并明确标注不是连通性探测结果。保留紧凑布局、搜索、筛选、分页与完整服务操作。

桌面宽度达到 1200px 时，服务详情使用非模态右侧工作区；可直接在网络中连续点选服务，不必关闭弹层。空工作区优先提示需要处理的真实服务。小屏转换为纵向路径与模态详情，避免强制横向拖动画布。节点旁的添加入口会带入节点上下文。

验证发现并修复了响应式 Dialog 重建会清空一次性凭证和草稿的问题：会话状态提升到布局之外，服务操作的进行中状态也按服务共享，防止尺寸变化后重复提交。实测备注在手机与桌面切换后保留。快捷入口可在桌面非模态工作区之上使用。

验证覆盖：连续切换服务、异常默认诊断、切换紧凑布局后工作区保持打开、按节点创建、390px 手机无横向溢出、深浅主题、跨尺寸草稿保留。类型检查、改动文件 lint 和生产嵌入构建通过。旧卡片与主视觉的未使用 CSS 已移除。
